## 1. Calendar contracts / context
Dates — календарные строки YYYY-MM-DD, не UTC midnight event timestamps. Строго существующая Gregorian date, поддерживаемый MVP диапазон 1900-01-01..2199-12-31; reject whitespace/coercion/ISO timestamp/offset/nonexistent day/пустую строку/неверный тип. PlannedTime — HH:mm, 00:00..23:59, nullable; без seconds/offset/Z. UI очищенные inputs переводит в null, не отправляет ''. Поле TIME — local wall-clock label в account timezone; conversion в instant/alarms/DST gap resolution не входит. Время 02:30 на DST gap day допустимо как label, не обещание запуска; просрочка определяется DATE, не прошедшим часом.
Server context: `{timezone,today,asOf}` (timezone из проверенного actor getAccountSettings, default UTC без INSERT; today YYYY-MM-DD; asOf ISO instant). Reference instant снять ровно один раз на read из часов PostgreSQL (SELECT current_timestamp либо эквивалент), тот же instant для всех секций/границ/метаданных этого read. Pure conversion instant→local date через explicit IANA timezone/Intl Gregorian/Latin digits, не process.env.TZ/browser zone/UTC slicing. Clock/instant инъекция для pure tests; никаких client clock/timezone overrides, production test-clock API/env/fixture endpoints.
Calendar addDays/addSevenDays — civil days, не прибавление 86400000 к instant в timezone. Валидировать границы диапазона и leap years (1900/2100 не leap, 2000 leap). Display DATE без сдвига дня из-за parse YYYY-MM-DD→instant→local formatter. Timezone change не переписывает dates/time: меняет вычисленный today/видимость/badges на следующем read.

## 2. Write API / atomic merge
POST /api/v1/tasks расширяется до `{title,plannedDate?:date|null,plannedTime?:time|null,deadlineDate?:date|null}`; отсутствующие fields defaults NULL, прежний `{title}` остаётся Inbox create. Project/parent/notes/priority/recurrence/owner/revision/order input по-прежнему forbidden. Quick-add Today передаёт явный displayed server-context today как plannedDate; client не выбирает timezone.
PATCH item расширяется до непустого subset `{title?,completed?,plannedDate?,plannedTime?,deadlineDate?}`. Title/completed rules TASK-007 сохраняются. Null разрешён только для schedule fields. Unknown/snake_case/неверный тип →400 без DB write/journal. DTO additive: прежние поля + `plannedDate:date|null,plannedTime:HH:mm|null,deadlineDate:date|null`; owner/notes/прочие вне scope не отдавать. GET item/POST/PATCH/collection возвращают единый extended DTO.
Validate cross-field merge ПОД существующим owner task lock: plannedTime ненулевой требует результирующий plannedDate. POST без date + time →400; PATCH только time при существующем date допустим, при date=NULL →400 field=plannedTime. PATCH plannedDate:null автоматически clears plannedTime, если time omitted/null; explicit plannedDate:null+nonnull time →400. PATCH только plannedDate nonnull сохраняет прежнее time; только time:null не очищает date. Deadline никогда не меняется вследствие смены/очистки плана. Earlier deadline than plannedDate разрешён (не автосдвиг/не ошибка).
Date fields/title/completed combined — одна transaction/revision+1 на effective mutation; no-op не меняет revision/timestamps/journal. SQL now timestamp policy TASK-007 сохранить. Учитывать PG TIME HH:mm:00 vs API HH:mm при сравнениях no-op. Не переписывать omitted поля, notes/priority/project/parent/order/created_at/recurrence; normalized schedule values используются только там, где поле явно изменяется/автоматически clears time. Completion journal occurrence_date остаётся NULL для one-off; rollback/unique/no-op/reopen/soft delete semantics TASK-007 сохранить. Concurrent schedule update vs title/complete не теряет unrelated fields; archive lock/child+recurrence409/foreign==missing404/deleted semantics неизменны.
Tasks POST/PATCH streaming body limit теперь **4 KiB**, explicit task-specific constant/argument: максимальный 500-code-point emoji title с schedule fields должен помещаться. Shared helper/default 2KiB, Projects/Settings и DELETE limit2KiB не менять. ## 3. Read API и owner filters
GET /api/v1/tasks поддерживает `view=inbox|today|upcoming` (default inbox), `status=open|completed|all` (default open), `start=YYYY-MM-DD` только для upcoming. Duplicate/unknown keys/values, start в другом view, диапазон start..start+6 вне supported dates →400. Client timezone/today/owner/reference instant не принимаются. Прежний GET без view/status defaults и status-only Inbox работает.
Ответ единой формы `{tasks:TaskDTO[],context:{timezone,today,asOf,view,startDate?,endDate?}}`. Для upcoming startDate=start или today, endDate=start+6 inclusive; остальные views не возвращают range fields. Новые поля additive; прежние clients читающие tasks array остаются совместимыми.
Все working views server-filtered: own non-deleted ROOT one-off tasks, project NULL либо own project archived_at NULL. Child/recurrence не включать до TASK-009/011. status=open/completed/all фильтрует completed_at, default open во всех views. GET item по-прежнему читает own non-deleted task в других состояниях; mutations unsupported/archived rules не ослаблять. Failed query не превращается в []/default timezone. No cross-user cache.
Inbox: planned_date=NULL, прежний stable sort_order/created_at/id. Deadline сам по себе не убирает task из Inbox.
Today: union plannedDate<=today ИЛИ deadlineDate<=today; каждая task в результате один раз. Четыре взаимоисключающие секции по приоритету:
1. plannedDate<today → «Просрочен план»;
2. plannedDate=today → «На сегодня»;
3. ещё не включённые deadlineDate<today → «Дедлайн просрочен»;
4. ещё не включённые deadlineDate=today → «Дедлайн сегодня».
Таким образом future/undated plan с deadline<=today виден независимо от плана; задача с overdue plan+deadline today остаётся только в1 с отдельным deadline badge. Past deadline warnings не требуют записи/reschedule. Срок позже today не создаёт отдельную Today section; для попавшей по плану task показывать дату deadline независимо.
Open rows: badge deadline<today просрочен / =today сегодня / >today дата. Completed rows в explicit completed/all mode: даты показываются нейтрально, не заявлять выполненную task просроченной; headers прошлых plan/deadline секций нейтральные («План до сегодня», «Дедлайн до сегодня»). Default Today остаётся incomplete; completed mode нужен для reopening scheduled задач.
Today stable ordering: section rank 1..4; внутри1 plannedDate ASC, plannedTime ASC NULLS LAST, sort_order/created_at/id ASC; внутри2 time NULLS LAST + stable triple; внутри3 deadlineDate ASC + stable triple; внутри4 stable triple. Grouping/ordering helpers share one contract между service/UI, без дублей.
Upcoming: только plannedDate в [startDate,endDate], включая оба конца; 7 day groups даже если день пуст. plannedDate ASC, plannedTime ASC NULLS LAST, sort_order/created_at/id ASC. Группировать по plannedDate, не deadlineDate; deadline показывать badge, не переносить task в другой день. Deadline-only task в Upcoming не вставлять как fake plan (видна в Inbox/Today при due). Браузинг prev/next7 days + current7 days, корректный month/year/DST переход. В completed mode reopening работает, даты не меняются.
