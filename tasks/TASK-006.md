## 1. Project behaviour и service layer
- Actor только из проверенной текущей session через requireUser; page использует requireUserOrRedirect. Layout guard не заменяет защиту каждого API entry point. Server-only business service получает только trusted server-derived actor; client user_id/owner_id ни в query, ни в payload/header actor не задаёт.
- Каждый list/read/update WHERE owner_id=actor.id; item update обязательно WHERE id AND owner_id, без read-by-id → unscoped update. Чужой существующий id и неизвестный id дают одинаковый 404 NOT_FOUND без раскрытия имени/owner/archive state. Несуществующий/чужой проект не создаётся через PATCH.
- Create генерирует id на сервере/DB, owner из session, archived_at=null, sort_order default 0. Имя trim, непустое, <=120 Unicode code points (согласовано с PG char_length, не UTF-16 units); неизвестные поля/тип/null запрещены. Повторяющиеся имена разрешены, uniqueness не добавлять. Names с markup показываются как текст, не HTML.
- Rename разрешён и для активного, и для архивного своего проекта; id/owner/created_at/sort_order неизменны, updated_at явный server write. PATCH непустой subset name/archived, комбинированный PATCH меняет поля атомарно и не теряет unrelated updates.
- Archive sets archived_at server timestamp; повтор archive=true сохраняет исходный archived_at, повтор restore=false остаётся null. При следующем новом архивировании после restore новый timestamp допустим. Restore возвращает проект в активный список, сохраняет id/name/order/created_at. Atomic owner-scoped UPDATE; last DB write wins для одновременной записи одного поля, revision/ETag не вводить.
- Archive/restore НЕ удаляют проект и НЕ меняют связанные tasks: никакого cascading completion/delete/detach/reschedule. Projects archived исключаются из default active list; доступны в archived/all lists и owner item read. Исключение их задач из будущих task queries и запрет добавления в архив — инварианты TASK-007+, не новые task APIs сейчас.
- Стабильная сортировка list: sort_order ASC, created_at ASC, id ASC (полный tie-break). No sort_order input/reorder API; сохранённое значение не сбрасывать. Отсутствие данных — честный empty result, ошибки не маскируются пустым списком. Нет глобального кэша между requests/users.

## 2. Versioned HTTP contract
Project DTO: `{id:string,name:string,archivedAt:string|null,createdAt:string,updatedAt:string}` (timestamps ISO8601). Owner не возвращать. DTO один для всех endpoints.
- GET /api/v1/projects: 200 `{projects:ProjectDTO[]}`, default status=active. Единственный query `status=active|archived|all`; unsupported/duplicate query keys/unknown values →400. Все lists строго owner-scoped.
- POST /api/v1/projects: JSON `{name:string}` →201 `{project:ProjectDTO}`. Unknown fields включая id/owner_id/sort_order/archived запрещены. POST не обязан быть idempotent; UI не отправляет double submit и не делает слепой автоматический retry неоднозначной записи.
- GET /api/v1/projects/[projectId]: 200 `{project:ProjectDTO}`, активный или архивный своего actor. Invalid UUID syntax →400 VALIDATION_ERROR; valid unknown/foreign UUID →404 NOT_FOUND.
- PATCH /api/v1/projects/[projectId]: JSON непустой subset `{name?:string,archived?:boolean}` →200 `{project:ProjectDTO}`. Reject empty/unknown/null/array/wrong types; validation не пишет DB. Item endpoints query не поддерживают (400). DELETE не реализовать.
- Cookie auth текущего приложения; 401 UNAUTHENTICATED для валидного anonymous запроса. Mutations server-side Origin exact configured BETTER_AUTH_URL origin; missing/null/foreign →403 FORBIDDEN_ORIGIN, не доверять Host/Forwarded. Не полагаться на Better Auth handler CSRF для собственных routes. No wildcard CORS.
- JSON media type application/json (с parameters допускается), malformed JSON 400, другая media type 415, body >2KiB 413 (потоковый лимит, не только Content-Length), query/payload/id validation 400, unexpected failures 500 INTERNAL. Ошибка envelope `{error:{code,field?}}` без raw input/SQL/stack/cookie/email. Не создавать project при любой ошибке.
- Все success/errors private,no-store. Parsing/auth/origin/error mapping — transport, общая validation/persistence — service. Не вводить параллельный Server Action с дублирующими правилами. Никаких external/native/MCP credentials пока.
