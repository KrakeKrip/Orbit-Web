## 1. Данные и service boundary
- Доверенный actor только через requireUser()/requireUserOrRedirect() принятого TASK-004. Layout guard не заменяет проверку API/доступного server entry point. Lower-level service получает только server-derived actor, не client owner_id.
- Данные только user_settings WHERE user_id=actor.id. Не возвращать настройки других users и не позволять body/query/header задавать actor.
- До первой записи GET возвращает эффективные defaults `{timezone:"UTC",theme:"system"}` без INSERT/скрытой миграции. Существующие users без settings работают; settings row не добавлять в auth signup/bootstrap.
- PATCH создаёт одну row при отсутствии (PK user_id), используя defaults для остальных полей. При конфликте изменяет только явно переданные поля. Theme-only и timezone-only PATCH не перетирают второе поле; concurrent updates разных полей сохраняют оба изменения. Atomic PostgreSQL upsert, не read-all → write-all. Один и тот же field при конкурентной записи: last completed write wins; settings revision/ETag не требуются.
- created_at сохраняется; updated_at обновляется явным server write. Invalid request ничего не меняет, в том числе не создаёт default row. Повтор корректного PATCH безопасен; без upsert чужих users.
- No cross-request/global auth/settings cache. Любой cache в браузере scoped по actor, смена аккаунта отменяет/игнорирует устаревшие ответы; service errors не превращать в успешные defaults.

## 2. Versioned HTTP contract
GET `/api/v1/settings`: 200 `{settings:{timezone:string,theme:"light"|"dark"|"system"}}`.
PATCH `/api/v1/settings`: JSON object с непустым подмножеством timezone/theme, 200 тот же полный response. Не принимать user_id/owner_id/id и неизвестные поля, null, arrays, пустой object или неверные типы. Не возвращать email/tokens/hash/DB stack/сырой SQL.
Все ответы, включая ошибки: Cache-Control private, no-store. Ошибки: 401 `{error:{code:"UNAUTHENTICATED"}}`, 400 VALIDATION_ERROR (опционально поле timezone/theme без raw input), 403 FORBIDDEN_ORIGIN, 415 UNSUPPORTED_MEDIA_TYPE, 500 INTERNAL. Malformed JSON — 400, неподходящий Content-Type — 415. Ограничить PATCH body разумным размером (например 2 KiB), 413 PAYLOAD_TOO_LARGE; Content-Length не единственное доказательство размера. Query parameters для settings route не поддерживаются: reject 400; identity headers не учитываются.
Session cookies продолжают работать, никаких API keys/admin token/native auth пока нет. Для PATCH обязательно server-side Origin проверка точного configured BETTER_AUTH_URL origin, missing/null/hostile Origin → 403; не брать разрешённый origin из Host/X-Forwarded-* и не отражать произвольный CORS origin. Это собственный cookie mutation endpoint: защита Better Auth routes сама его не защищает. UI same-origin fetch; GET без Origin допустим. Session проверяется до выполнения mutation; анонимный вызов не создаёт row.
Transport только parsing/auth/origin/error mapping; общая validation/data logic в service, пригодная будущим clients. Не добавлять дублирующий Server Action с отдельными правилами или общий CRUD framework.

## 3. Валидация timezone/theme
Theme строго enum light/dark/system.
Timezone — строка известной именованной IANA zone в Intl runtime Node 24, плюс UTC. Trim допускается; пустые/неизвестные/слишком длинные (>100 chars) строки отвергать. Отвергать numeric offset форматы вроде +03:00/UTC+3/GMT+3: это не account IANA zone. Поддерживаемые named aliases допустимы, сохранить canonical resolved Intl timezone. Примеры positive: UTC, Europe/Moscow, America/New_York, Asia/Tokyo; negative: Mars/Olympus, empty, offset, wrong type. Intl.supportedValuesOf список не обязан включать UTC/aliases: не объявлять их невалидными только из-за отсутствия в этом списке.
Default UTC не определяется по browser/locale/IP пользователя. Автоматически не менять timezone на основе расположения. Уточнение UI объясняет, что timezone будет использоваться для Today/Upcoming/recurrence в последующих TASK; не делать вид, что эти алгоритмы уже работают.
